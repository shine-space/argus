---
title: "错误与异常恢复"
---

根据错误类型处理身份、权限、修订冲突和资源不可用。

## 同时检查 HTTP 与业务结果

JSON 接口先检查 HTTP 状态，再检查 `status`、`code` 和业务 `data`。流式响应开始前可能返回普通 JSON 错误；开始后的处理遵循具体事件合同。

## 常见状态

| HTTP | 典型含义 | 建议处理 |
| --- | --- | --- |
| 400 | 请求绑定或登录参数错误 | 按返回信息修正输入，不盲目重试 |
| 401 | 缺少、过期或无效身份 | 按认证流程恢复会话 |
| 403 | 当前权限不允许 | 停止操作，由授权负责人确认范围 |
| 404 | 对象不存在或不可读取 | 核对当前范围和对象来源 |
| 409 | 修订、幂等、状态或兼容冲突 | 重新读取原对象，处理差异 |
| 422 | 输入、模型能力或依赖合同不满足 | 根据明确条件修正配置或请求 |
| 429 | 当前执行容量受限 | 检查已有任务，遵守企业并发策略 |
| 503 | 服务或资源暂不可用 | 定位具体依赖，不重复创建业务写入 |

具体错误码以该接口与安装版本为准。例如应用接口可能返回 `APPLICATION_PERMISSION_DENIED`、`APPLICATION_CONFLICT`、`APPLICATION_RECORD_MIGRATION_REQUIRED` 和 `APPLICATION_ENVIRONMENT_CAPACITY`。

## 未知结果

连接断开或超时后，保留原请求标识和幂等键，查询原对象或任务。不要把未知结果当失败后重新执行付款、发送或其他业务动作。

## 提交问题

提供安装版本、接口路径、脱敏请求结构、对象或命令标识、时间及安全错误码。若响应提供请求追踪标识，也一并保留。不要提交访问令牌、密码、完整敏感文件或模型凭证。
